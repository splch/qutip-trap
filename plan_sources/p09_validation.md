# Part IV. Validation, delivery and provenance

## 9. Validation suite

Every module ships tests that reproduce published, verified numbers or closed forms. The suite is the definition of "correct" for this project: a change that moves any of these outside tolerance fails CI. Two kinds of rows share the tables and have different CI semantics. **Pinned tests** (closed forms, recomputed values, identities, conversions) fail the build; where a row states no tolerance, the default is 10⁻⁹ relative for closed forms and exact identities, the printed number of significant digits for recomputed values, and 10⁻¹² for operator identities. **Consistency anchors** (laboratory numbers quoted from a paper) are tracked metrics with the acceptance band stated in the row or, by default, the published uncertainty, or 20% where none is given; they report but do not fail the build, because Section 12 records that published fidelities cannot be reproduced from first principles without recomputing the mode structure and pulses under stated assumptions. Every row is written in the simulator's own conventions and names the Section 13 row it depends on; a source's convention appears only as a labelled conversion test. Multi-ion rows run with the resolved-mode set their device preset declares and the frozen-spectator contribution of Section 5.2 reported. All tests run in JOINT_EXACT mode unless marked.
