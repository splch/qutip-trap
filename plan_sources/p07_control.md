## 7. Control stack: native gates, compilation, scheduling and calibration

### 7.1 Native gate set

The simulator's native set is the one exposed by current trapped-ion cloud machines, because it maps one-to-one onto physical pulses:

- **GPi(φ)**: a π rotation about the equatorial axis at azimuth φ. Matrix (IonQ documentation [verified]): `[[0, e^{-iφ}], [e^{iφ}, 0]]`. Physical realization: a carrier pulse of area π with optical (or microwave) phase φ relative to the qubit's phase frame.
- **GPi2(φ)**: a π/2 rotation about the same axis. Matrix: `(1/√2)[[1, -i e^{-iφ}], [-i e^{iφ}, 1]]`. Physical realization: carrier pulse of area π/2.
- **RZ(θ)** (virtual): no pulse. Implemented by advancing the phase frame of the qubit so that every later pulse on that qubit carries an extra phase; zero duration, zero error, apart from the bookkeeping. This is exactly how the hardware does it [verified]; the sign of the frame shift is pinned in Section 7.6.
- **MS(φ0, φ1, θ)**: the Mølmer-Sørensen entangling gate between two qubits with per-qubit phases φ0, φ1 and entangling angle θ ∈ [0, π/2] (IonQ specifies angles in turns, 0 to 0.25 turns; the package accepts radians and turns explicitly). Fully entangling at θ = π/2. Physical realization: a bichromatic pulse on both ions with the beat-note phases set from φ0, φ1 and the amplitude or duration set from θ through the calibration table.
- **ZZ(θ)**: `diag(e^{-iπθ}, e^{iπθ}, e^{iπθ}, e^{-iπθ})` with θ in turns [verified, IonQ documentation, Forte-class]. Physical realization: a light-shift geometric-phase pulse, or an MS pulse wrapped in single-qubit pulses (the Quantinuum construction, also used on Forte [verified]).

The exact matrices, including the partially entangling MS form and the turns convention, are pinned by tests against the vendor documentation and against the research-run extraction; the package documents the phase convention it adopts (Section 13) and provides converters.

### 7.2 Compiler

Input IR: a list of operations `(name, qubits, params)` supporting the native set plus a standard set (X, Y, Z, H, S, T, RX, RY, RZ, CNOT, CZ, SWAP, controlled-phase, arbitrary U3). Compilation rules:

1. Single-qubit standard gates become at most two GPi2 pulses with virtual RZ: any U ∈ SU(2) equals, up to a global phase, RZ(α)·GPi2(0)·RZ(β)·GPi2(0)·RZ(γ), a ZXZXZ Euler decomposition that is complete because GPi2(0)·RZ(β)·GPi2(0) is RY(−β)·RX(π) up to phase and RX(π) is a Pauli, so the angles are the ZYZ Euler angles of U·X (checked on 20 random SU(2) targets to a residual of 0 **[recomputed here]**); every RZ is absorbed into the phases of later pulses. Arbitrary-area carrier pulses exist as an internal capability of the pulse layer, used by the Rabi scans and by the composite-pulse templates of Section 7.7, but the exported native set is GPi, GPi2, MS and ZZ only, so the IonQ JSON round trip of Section 9.6 holds. The compiler tracks a phase frame per qubit and rewrites the phase of every subsequent pulse (phase propagation).
2. CNOT and CZ become one MS (or ZZ) plus single-qubit gates using the standard identities; controlled-phase with arbitrary angle becomes a partially entangling MS or ZZ.
3. The compiler verifies each compiled block against its target unitary numerically (up to global phase) before scheduling; this is the one place ideal matrices are used.
4. Measure, reset and recool are schedulable operations of the IR and of `Schedule` from the first release, so the pipeline shape is prep → [gates | measure | reset | recool]* → results; the first release executes measurement only as the terminal stage and refuses a mid-circuit measure or reset with a clear error, but the IR, the scheduler and `Result` already carry the positions, so that adding the physics of Section 8.5 (detection recoil, neighbour Stark shift, depumping, recooling and re-preparation of the measured ion) is a stage implementation and not a pipeline change (Section 1.3 names a QEC stack as a client, and that is the client that needs it; 2026-09-04 experimentalist critique) **[corrected: critique, 2026-09-04]**.

### 7.3 Scheduler

Turns native gates into pulses with absolute times:
- single-qubit gates on distinct ions may run simultaneously if the device model allows parallel addressing, otherwise sequentially;
- MS gates are serialized (one at a time per crystal in the first release);
- between pulses the scheduler inserts idle intervals with the device's minimum gap, during which the evolution module applies free evolution with heating and dephasing;
- pulse parameters come only from the calibration table (Section 7.5), never from the device's hidden "true" values, so that the simulated machine behaves like a machine whose knowledge of itself is imperfect in exactly the way a laboratory's is; the derived values are allowed only as tagged initial guesses for the calibration scans, and an entry the calibration could not establish is `uncalibrated` and refuses to schedule rather than falling back to them.

### 7.4 Pulse representation

A `Pulse` holds: target ions; drive type; tones, each with detuning schedule δ(t), phase schedule φ(t) and amplitude envelope Ω(t) (a callable or sampled array); duration; the effective wavevector; and metadata (which gate, which modes are intended to close). Envelopes include square with smooth (sine-squared or Blackman) edges, and the segmented or continuous AM/FM/PM waveforms produced by the pulse-shaping solvers for multi-mode gates. The shaping solvers implement the closure conditions on all modes and the entangling-phase condition as constraints (linear in amplitude for segmented AM; nonlinear for FM), with the robustness conditions the literature uses (first derivative of the displacement with respect to detuning equal to zero) as options; Section 4 gives the equations they satisfy.

### 7.5 Calibration emulation

The calibration layer runs simulated experiments and fits them the way the laboratory does:

1. **Carrier Rabi frequency per ion**: Rabi flopping scan of pulse duration on the carrier; fit to the expected curve including the Debye-Waller reduction from the thermal motion of the current preparation; yields the π time and the amplitude scale per ion (which also reveals the addressing beam's intensity profile).
2. **Mode frequencies**: sideband spectroscopy (scan detuning near ±ω_m, observe excitation) or Ramsey-type motional spectroscopy; yields ω_m for the modes used and, from sideband asymmetry, n̄ per mode.
3. **Phase frame alignment**: a Ramsey experiment establishes the reference phase for each ion's frame; MS phase scans establish the entangling axis relative to it.
4. **Entangling gate**: for the chosen pair, scan the detuning and amplitude (or duration) of the bichromatic pulse; fit populations and parity oscillations to find the closure point and χ = π/4; store amplitude, detuning, duration and the phase offsets.
5. **Detection threshold and window**: histogram bright and dark photon counts on the simulated readout model; choose the threshold minimizing the average error; store the window length.
6. **Heating rate**: delay-scan of sideband asymmetry; store measured n̄-dot per mode (used to schedule recooling where the device has it).
7. **Stark shift**: a Ramsey experiment with the gate beams on and detuned, per (ion, beam), fitted for the differential light shift that sets the MS phase; stored in `stark`.
8. **Crosstalk**: drive ion i, fit the Rabi rate and phase on every neighbour j; stored in `crosstalk` as ε_ij.
9. **Field**: the clock-point or Zeeman-splitting scan that fixes B and its drift, stored in `field`, run first because every other fit reads the Zeeman sensitivities.

The experiments form a dependency graph that `calibrate()` follows and never reorders: field, then micromotion compensation, then mode frequencies, then carrier Rabi and Stark, then crosstalk, then the entangling-gate scans, then detection and heating, and a downstream fit refuses to run while an upstream entry it reads is `uncalibrated` (a mode-frequency fit on an uncompensated ion carries J₁ micromotion sidebands; the second revision declared the experiments as an unordered list, and its `CalibrationTable` named three entries, `stark`, `crosstalk` and `field`, for which no experiment existed; 2026-09-04 experimentalist critique) **[corrected: critique, 2026-09-04]**.

Calibrations are cached per device configuration and per noise seed; the tests in Section 9 require that calibrated parameters agree with the device's true derived parameters within the uncertainty the fits report, and that the gates built from them reach the fidelity the noise model predicts.

**Bootstrap, fits and failure.** The first calibration has no table to read, so each experiment starts from the device's derived values as initial guesses, tagged `seed` in the table: the carrier scan spans at least ten derived π times and fits Rabi frequency and contrast, with n̄ taken from the sideband-ratio thermometry of Section 4.2.7 rather than from the Debye-Waller envelope, whose decay over about 1/(η²n̄) Rabi periods makes a three-parameter fit to less than one period degenerate; 2026-09-04 critique, all four lenses) **[corrected: critique, 2026-09-04]**, and must report an uncertainty below the sub-kilohertz need of the FM pulse solvers (the first version of this plan specified scans that could neither identify n̄ nor resolve a 10 kHz sideband with 64 steps over 600 kHz; caught by the 2026-09-04 experimentalist critique); a micromotion-compensation experiment (rf-photon correlation, the sideband-ratio method on the rf micromotion sideband, and two-direction Doppler nulling, Berkeland 1998) scans the shim voltages, returns the residual β per beam direction and stores shims and β in the table, so that compensation is calibrated, drifts with the stray field between calibrations and is re-nulled like a laboratory re-nulls it; a Ramsey-frequency experiment measures each qubit's frequency and stores it, because Section 7.3 forbids the scheduler the true value and every pulse needs a detuning; the entangling-gate scan spans ±30% in amplitude about the closure amplitude the pulse solver predicts at the calibrated mode frequencies and fits populations and parity contrast; the detection calibration draws 10⁴ bright and 10⁴ dark records; the heating-rate scan uses delays up to 10/ṅ_derived. Every fit reports an uncertainty, and a fit that fails to converge or lands at the edge of its scan range marks the entry `uncalibrated`, which the scheduler refuses to use. The calibration package sits above `control` and `dynamics` and drives them through the `PulseEngine` protocol (Appendix E), and `control.schedule` reads only the plain `CalibrationTable` data object, which is what breaks the schedule-calibration import cycle of the first layout. Calibration by simulated experiment is hours of pulse integrations at the rates of Section 11.1, so it is cached, invalidated rather than silently regenerated when a device parameter changes, and run as an explicit job (Section 14.4).

**Age, drift and cost.** Every entry carries the time it was fitted and the noise sample it was fitted under; slow parameters are trajectories with a correlation time (Sections 6.2 and 6.3), so the calibration error starts at the fit uncertainty and grows with elapsed time, `run` takes the table and the run's start time as arguments, and a gate driven with a stale detuning is a reproducible failure mode rather than an impossibility. An optional servo (frequency feedforward, or periodic re-lock of a parameter with a stated bandwidth) high-passes the drift into the residual band, which is the mechanism behind the 50 Hz feedforward residual of Section 6.2; the first version of this plan sampled raw quasi-static drift against a once-computed table, which double-counts the slow band that every laboratory servos away (caught by the 2026-09-04 experimentalist critique). Because a full calibration by simulated experiment does not fit the compute budget of Section 11 beyond two ions (about 400 detuning-by-amplitude points at 2 s each per pair at joint dimension 256 is 13 minutes per pair and 94 hours for the 435 pairs of a 30-ion device, and the per-pair joint space for N ≥ 4 exceeds the ceiling), the default calibration is a surrogate: the closed-form α_m and χ_m integrals of Section 4.4.3 on the derived mode structure, corrected by a small number of exact spot checks (one pair per distinct pair class, at the resolved-mode set of Section 5.4), with the full simulated-experiment path an opt-in audit that reports the surrogate's error; Section 9.8 likewise validates GATE_LOCAL against JOINT_EXACT only where JOINT_EXACT is affordable **[corrected]**.
