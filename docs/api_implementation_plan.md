# qutip-trap API implementation plan

*Status: plan, 2026-09-11, against commit 7a26a27 (v0.1.0) plus the uncommitted Qiskit adapter. It sequences the proposal in [`api_proposal.md`](api_proposal.md) into work an implementer can pick up item by item. Sizes are rough, for one implementer who knows the tree; they are not commitments.*

## 1. Ground rules that hold in every phase

- **Nothing physical changes.** `validation/scripts/run_checks.py --report` against the committed outputs is the regression guard for every number the simulator produces; each phase ends with it green, with `uv run pytest` green, and with the timing benchmarks (`validation/scripts/bench_*.py`) within their bands. `Machine.run` is a delegation to today's `run`; zero new work enters the hot path.
- **Additive first, deprecate second, remove third.** Every phase adds names and behaviour; a name is deprecated only once its replacement has shipped in a release; a removal happens no earlier than two minor releases after its warning, always with a warning-free path. `tests/test_api_freeze.py` stays untouched except where a declared field is widened, which goes into its allowed-divergence tables with the reason, as the existing entries do.
- **Appendix E moves with the code.** Amendments go to `plan_sources/p17_interfaces.md`, PLAN.md is re-rendered with `plan_sources/render_plan.py`, and the freeze test reads the result; the amendment and the code land in the same change so the test never sees one without the other.
- **Hash stability.** A new field on `Device` (or any hashed record) enters `qutip_trap/hashing.py`'s canonical serialisation only when its value differs from the field's default. Every existing device hash, every cached calibration table and every digest a test compares therefore survives. Four test modules compare device hashes today (`test_presets.py`, `test_full_calibration.py`, `test_trap_model.py`, `test_run_circuits.py`).
- **Every new public name ships complete**: a docstring that states its units and conventions, a place in a rung module's `__all__`, a line in the docs, and a test. The public-surface test of Phase 0 enforces the first three mechanically.
- **The app is a client.** Core changes never depend on app changes; the app adopts each phase's additions in a separate change and deletes the workaround it replaces, so `CORE_GAPS` in `qutip_trap_app/src/qutip_trap_app/core.py` shrinks phase by phase and is empty at the end of Phase 3.

## 2. Phase map

| Phase | Release | Theme | Main deliverables | Rough size |
|---|---|---|---|---|
| 0 | none | groundwork | deprecation helper, public-surface test, docs-convention tests, the v2 IonQ order settled, import-time check | 1 week |
| 1 | 0.2.0 | the executor and the ladder | `BeamRoles` on `Device`, `Machine`, `Level`, the option objects (behind the machine), the `Circuit` builder, rung modules and the lazy root, `Result` envelope and exporters, `progress`, truncation warnings | 3 to 4 weeks |

Total: roughly nine to twelve weeks of focused work. Phases 1 and 2 are the long poles; Phase 0 is small but nothing in Phase 1 should start before its two tests exist.

## 3. Phase 0: groundwork (no public change)

**0.1 The deprecation helper.** New `qutip_trap/_compat.py`: `QutipTrapDeprecationWarning(DeprecationWarning)`; `deprecated(*, deadline: str, fix: str)` as a function and class decorator, the deadline validated against `^v\d+\.\d+$` and `fix` required to be a full sentence; `deprecated_parameter(*, name: str, deadline: str, fix: str, rewrite: Callable[[dict], dict])` that rewrites a call's keyword arguments in place and warns once per call site; `deprecated_alias(new, *, deadline, fix)` for renamed functions and methods. Tests in `tests/test_compat.py`: the deadline regex, the warning category and message, the rewrite producing identical results, `warnings.simplefilter("error")` in the test session so a deprecated path used inside the package itself fails CI. Reference: Cirq's `_compat.deprecated` and `deprecated_parameter(match, rewrite)`.

**0.2 The public-surface test.** New `tests/test_public_surface.py`: a table of rung modules (starting with `qutip_trap.api` alone) whose every `__all__` name must resolve, carry a docstring, and appear in backticks in at least one page under `docs/`; every frozen dataclass among them must round-trip through `dataclasses.replace` unchanged. Phases add modules to the table as they create them. Reference: Cirq's `json_test_data/spec.py`, which forces a per-name decision.

**0.3 Convention tests in the docs.** In `tests/test_docs.py`: the bit-order sentence ("qubit 0 is the least-significant bit, the rightmost character") appears exactly once across `docs/` and the package's docstrings say the same thing; the tensor-order statement for the native gate matrices appears once (`control/native.py`) with the test that `ms(...)` equals the SWAP conjugate of the `qiskit_ionq` form (skipped without qiskit-ionq). Reference: CUDA-Q's two pages that contradict each other.

**0.4 Settle the IonQ v2 character order.** The v0.4 spec defines the `{"probabilities": {"registers": {"output_all": ...}}}` envelope but not the character order inside a bitstring; the vendor survey reports `q[0]` leftmost. Settle it against IonQ's result documentation or a dry run of `x q[0]` on three qubits against the service, record the answer in `qutip_trap/io/ionq.py`'s module docstring, and write the asymmetric fixture (`x q[0]` on three qubits gives `"1"` in v1 and the settled string in v2) into `tests/test_m6_results_export.py` before the exporter is touched in 1.7.

**0.5 Import-time check.** A line in `.github/workflows/ci.yml`'s core job that prints `python -X importtime -c "import qutip_trap"` totals for `qutip_trap` and `qutip_trap.api`, and a test that `import qutip_trap` stays under 0.2 s on the CI runner (today 0.05 s locally; `qutip_trap.api` is 0.49 s). The lazy root of 1.6 must not regress it.

**0.6 Names.** Decide and record, in a short "Vocabulary" section at the top of `docs/conventions.md`: `Machine` (against `Emulator`, `Backend`), the recommended alias `trap`, the rung module names (`circuit`, `schedule`, `dynamics`, `physics`, `interop`, `experimental`), the `Level` members, and the error-model naming discipline (`p_*` probability, `*_rate` per second, `*_ratio` fraction of another probability, `*_scale` multiplier). Everything in Phases 1 to 3 uses these names; changing one later costs a deprecation cycle.

Done when: `tests/test_compat.py`, `tests/test_public_surface.py` and the two docs tests pass; the v2 order is written down with its source; CI prints import times.

## 4. Phase 1: 0.2.0, the executor and the ladder

Ordered by dependency. Items 1.1 and 1.2 first; 1.3 needs both; 1.4 can proceed in parallel with 1.3 and must land before 1.3 is documented; 1.5 to 1.9 are independent of each other; 1.10 last.

**1.1 `BeamRoles` on `Device`.** In `qutip_trap/device/model.py`: a frozen `BeamRoles(gate: Mapping[int, GateDrive] | None = None, entangling: Mapping[int, GateDrive] | None = None, detection: int | None = None)` and `Device.roles: BeamRoles = BeamRoles()`. The resolution rule for `None` fields is today's `control/schedule.default_gate_drives` and `light/roles.detection_beams`, moved behind `BeamRoles.resolve(device) -> ResolvedRoles` so the scheduler, `run`, `calibrate`, the experiments and the benchmarks read one function; the old keyword arguments `gate_drives=` and `entangling_drives=` stay accepted and take precedence when given (they are deprecated in Phase 2). `hashing.py` skips a field equal to its default, so no existing digest changes. `device/presets.py` builds its devices with explicit roles; `DevicePreset.run_kwargs()` becomes an empty dict for presets whose device carries roles and warns through `_compat` when called. Tests in `tests/test_beam_roles.py`: inference equals the old default for the fixtures of `tests/m6_fixtures.py`; each preset's `device.roles` equals its old drive maps; `Device.hash()` of every preset is unchanged (assert against the digests the presets produce at 7a26a27, captured once into the test); `run(bell, device, shots)` with no drive keyword reproduces `docs/examples.md`'s histogram bit for bit at the same seed. Appendix E: `Device` gains `roles` (prose amendment in the freeze test's `PROSE_AMENDMENTS`).

**1.2 `Level` and its reason.** In `qutip_trap/run/levels.py`: `class Level(StrEnum): AUTO, JOINT_EXACT, GATE_LOCAL`, accepted wherever the strings are today; `resolve_level` returns `(Level, reason: str)` with the dimension and non-zero counts against `joint_dimension_max` and `nnz_max`; `Diagnostics.level_reason: str = ""` (a field with a default, a widening). Tests: `Diagnostics.level_reason` names both numbers on the two-ion Bell run and on a forced level.

**1.3 `Machine`.** New `qutip_trap/machine.py`: the frozen dataclass of proposal Section 4.2 with `device`, `table`, `physics`, `numerics`, `readout`, `level`, `name`; methods `run`, `compile`, `schedule`, `calibrated`, `estimate`, `engine`, `hash`, and `error_model`/`specs`/`submit` raising `NotImplementedError` naming their phase (the repository's existing convention for later milestones). `run` translates the option objects into today's `run` keyword arguments through one function `to_run_kwargs(physics, numerics, readout)` and calls `run/job.run`; `compile` calls `compile_with_report`; `schedule` calls the compile-calibrate-schedule prefix of `run` (factor that prefix out of `run/job.py` into `run/pipeline.py` so both call one function); `calibrated(method="closed_form"|"experiments", **scans)` calls `calibration.calibrate` and returns a machine with the table pinned; `estimate(circuit)` runs `resolve_level` with the schedule's actual space and the Section 11.2 cost model; `engine` returns a `JointExactEngine` configured from `numerics`; `hash()` digests the device hash, the table's hash and the three option objects. Tests in `tests/test_machine.py`: `Machine(device).run(bell, 2000, seed=0)` equals `run(bell, device, 2000, seed=0)` field for field (bitstrings, spam, diagnostics with `wall_clock_span_s` excluded); `schedule` equals `control.schedule.schedule` on the same table; `calibrated().table.device_hash == device.hash()`; `replace(level=Level.GATE_LOCAL)` produces `Diagnostics.level == "GATE_LOCAL"`; `estimate` matches the diagnostics of the run that follows; `hash()` changes when and only when device, table or policy change.

**1.4 The option objects.** New `qutip_trap/options.py`: `Physics`, `Numerics` with the nested `Integration`, `Truncation`, `Trajectories`, `GateLocal`, `Parallel`, and `Readout`, each a frozen dataclass with two-line field docstrings, `__post_init__` validation moved from `SolverOptions.__post_init__`, `asdict()`, and a `from_mapping()` that accepts dicts (Qiskit's alias rule). `to_run_kwargs` is the only place that knows today's keyword names. `SolverOptions` is unchanged in this phase and remains what `Numerics` is built from internally. Tests in `tests/test_options.py`: every `SolverOptions` field has exactly one home in `Numerics` or `Physics` (a table in the test, so a new field cannot be added to one without the other); defaults reproduce today's defaults; validation errors match `SolverOptions`'s; `Machine(...).run` with non-default options equals `run(...)` with the corresponding keyword arguments.

**1.5 The `Circuit` builder.** In `qutip_trap/control/compiler.py`: `Circuit(n_qubits, ops=(), measure=None, registers=None)` where `measure=None` means every qubit and `registers=None` means `{"c": measure}`; a persistent builder, one method per name in `NATIVE_GATES` and `STANDARD_GATES` generated from those tables (a `_with(op)` returning a new `Circuit` plus a loop that attaches the methods, so the module gains one mechanism rather than thirty methods), `measure(*qubits)`, `from_openqasm(text)`, `from_ionq(obj)`, `to_openqasm()`, `to_ionq()`. `io/openqasm.py`'s parser keeps `creg` names into `registers` and its `measure q[i] -> c[j]` mapping into the register map. Tests in `tests/test_compiler.py` and `tests/test_openqasm.py`: the builder equals explicit construction; the default measurement; `registers` survives an OpenQASM round trip; the freeze test's declared fields are unchanged (`registers` is an addition with a default). Appendix E: `Circuit.registers`.

**1.6 Rung modules and the lazy root.** New re-export modules `qutip_trap/circuit.py`, `qutip_trap/schedule.py`, `qutip_trap/physics.py`, `qutip_trap/presets.py` (presets returning machines; `DevicePreset.machine()` as the bridge) and `qutip_trap/io/qasm2.py` (`loads`, `dumps`), with `qutip_trap/io/ionq.py` gaining `loads`, `dumps`, `load_job`, `dump_job`; `qutip_trap/dynamics/__init__.py` exports `JointExactEngine`, `build_hamiltonian`, `BuilderOptions`, `BuiltHamiltonian`, `DriveRecord`, `prepare`, `State`, `Traces`, `HilbertSpace`, `SolverOptions`, `gate_channel` and the tomography records; `qutip_trap/__init__.py` exports the rung-0 names (`Machine`, `Circuit`, `Result`, `Level`, `Physics`, `Numerics`, `Readout`, `Progress`, `presets`, the rung modules, `__version__`) through a module `__getattr__` and `__dir__` so the import stays cheap. `qutip_trap/api.py` is byte-for-byte unchanged. Tests: the public-surface test's table gains every rung module; the import-time test; `tests/test_provenance_and_layout.py`'s import rules still hold.

**1.7 `Result` envelope and exporters.** In `qutip_trap/run/results.py`: `to_dict()`/`from_dict()` with `schema_version`, `qutip_trap_version`, `device_hash`, `machine_hash`, `shots`, `root_seed`, `created_at`, `duration_s`, then counts, probabilities, error bars, SPAM, heralds and a diagnostics summary (per-shot arrays opt-in); `reversed_bits()`; the exporters renamed `to_ionq_v1_probabilities/histogram/shots` and `to_ionq_v2_probabilities/histogram/shots` with the envelope, `output_all` and the circuit's `registers`, the old names kept through `deprecated_alias`; `from_ionq_v1_shots()`; the bit-order sentence on the `bitstrings` and `counts` docstrings. In `qutip_trap/io/ionq.py`: `dump_job(circuit, *, backend, shots, noise, settings, name, metadata)` emitting the v0.4 body, and the importer accepting `target` or `backend`. New `tools/schemas.py` generating `docs/schemas/result.schema.json` from the dataclass, checked in CI like the ledger tables. Tests in `tests/test_m6_results_export.py`: the round trip, the asymmetric fixture of 0.4 for v1 and v2, the schema validating a real result, `dump_job` validating against the v0.4 schema's required fields and `additionalProperties: false`.

**1.8 `progress`.** A frozen `Progress(stage, done, total, elapsed_s)` in `qutip_trap/run/results.py`; `run(..., progress=None)` and `Machine.run(progress=)`; the engine reports per pulse and per branch, `run` per sample. Tests: the callback sequence on the Bell run is monotone and ends at `done == total` for each stage; a callback that raises aborts the run cleanly.

**1.9 Truncation warnings.** In `qutip_trap/run/space.py` and `qutip_trap/hilbert/truncation.py`: `warnings.warn` (a `QutipTrapWarning` subclass) when a cap is clamped by `mode_dimension_max` and when the boundary population exceeds `boundary_population_max` after the retries, naming the mode and both numbers; the `Diagnostics` entries stay. Tests capture the warning on a deliberately clamped run and assert silence on the Bell run.

**1.10 Docs, examples, Appendix E.** `docs/examples.md` opens with the two-minute quickstart on the machine, followed by the existing examples (the executed-examples test covers both); `docs/limits.md` gains the truncation-warning rule; `plan_sources/p17_interfaces.md` gains a "2026-09 additions" block declaring `Machine`, `BeamRoles`, `Level`, `Physics`, `Numerics`, `Readout`, `Progress`, the `Circuit` and `Device` and `Diagnostics` fields, the `Result` methods and the io functions; PLAN.md re-rendered; the freeze test extended to the new declarations; `README.md`'s layout table gains `interop/`, `machine.py`, `options.py` and the rung modules; `docs/deprecations.md` created with the first entries (`DevicePreset.run_kwargs()`, the old exporter names), each "deprecated in 0.2.0, removed in 0.4.0 at the earliest".

Exit criteria for 0.2.0: `machine.run(bell, shots=2000)` reproduces the documented Bell histogram bit for bit against `run` at the same seed; `import qutip_trap` under the budget; the freeze test green with the amendments; the check scripts green; the app unchanged and green; no `**preset.run_kwargs()` left in `docs/`.

## 5. Phase 2: 0.3.0, options, the laboratory, the inverse direction

**2.1 Invert `run`.** `run/job.py`'s `run` becomes a thin function: it builds `Physics`, `Numerics` and `Readout` from its keyword arguments through `deprecated_parameter` rewrites (each old keyword named, with its new home in the message) and calls `Machine(device, table=..., physics=..., numerics=..., readout=..., level=...).run(circuit, shots, seed=, keep_final_state=, progress=)`. The pipeline that today lives in `run` moves to `run/pipeline.py`, called by the machine. `SolverOptions` becomes a `deprecated` constructor returning `Numerics` plus the three physics switches it carried, with the warning naming `Numerics` and `Physics`. Tests: every one of the 25 keyword arguments, passed the old way, warns once and produces a result identical to the object form; the check scripts and the whole test suite pass under `-W error::QutipTrapDeprecationWarning` once the tests themselves are moved to the new form (that move is part of this item: 94 `gate_drives=` occurrences in the package and tests go to zero outside `tests/test_beam_roles.py`).

**2.2 The laboratory on machines.** Every function in `qutip_trap/experiments/`, `qutip_trap/calibration/` and `qutip_trap/benchmarks/` accepts `Machine | Device` as its first argument (a `Device` is wrapped in a default machine, and warns from 0.4.0), drops `**run_kwargs` and `gate_drive=` (roles come from the device), and takes its scan parameters as keywords with units in their names. `calibrate(machine, *, method="closed_form" | "experiments", experiments=..., seed=...)` returns the `CalibrationReport` on every call; `calibrate_with_report` and `compile_with_report` become `deprecated_alias`es; `machine.calibrated(method=)` is the same call. Tests: each experiment on the machine equals the same experiment on the device with the drive keyword at the same seed (one parametrised test over the experiment table of `calibration/experiments.py`).

**2.3 Typed experiment results.** In `qutip_trap/experiments/result.py`: `ExperimentResult` keeps `data`, `fitted`, `model`, `provenance_id`, `value()`, `uncertainty()`, `converged`, and gains `requested`, `realized`, `quality`, `created_at`, `chi2`; subclasses `RabiScan`, `RamseyFringe`, `SidebandSpectrum`, `ThermometryResult`, `HeatingRateFit`, `MSScan`, `ParityScan`, `DetectionHistogram`, `StarkScan`, `CrosstalkScan`, `FieldScan`, `MicromotionScan`, `CrystalImage` with the fitted parameters as typed attributes and a `plot()` that needs the `plot` extra. `realized` comes from the played schedule (`control/played.py`), so a scan reports the pulse the electronics could play. Tests: every experiment returns its subclass; `value(key)` equals the typed attribute; `realized` differs from `requested` when the hardware chain quantises and equals it otherwise.

**2.4 Table proposals, overrides and kinds.** In `qutip_trap/control/table.py`: `CalibrationTable.with_params(**overrides)`; `updated_with(result) -> CalibrationTable` that maps an `ExperimentResult` subclass onto the entries it sets (the mapping lives next to `calibration/experiments.py`'s dependency order, one place); `CalEntry.kind: Literal["setpoint", "characterisation"]` with a default derived from the entry's table field; the lookup precedence for waveforms and per-beam entries written as a docstring rule (most specific match over gate, parameters, ions). The app's `requests.py` and `resim.py` adopt `with_params` and delete their own override code. Tests: `with_params` rejects unknown keys; `updated_with` on a `RabiScan` changes exactly the Rabi entry and stamps `fitted_at_s`, `sample_id`, `experiment`; the app's `test_requests.py` passes on the core operation.

**2.5 Quiet `NoiseModel`, `Device.specs`, `Device.to_dict`.** In `qutip_trap/noise/model.py`: every spectrum and drift optional with defaults meaning "off", `NoiseModel()` equal to today's `quiet_noise_model()` (which becomes a deprecated alias), `summary()` returning `{name: (value, unit)}` for the channels that follow from what was set, `from_experiments(results)` for the heating-rate case first. In `qutip_trap/device/model.py`: `specs()` rendering the derived quantities with their provenance ids, `to_dict()`/`from_dict()` with `docs/schemas/device.schema.json` from `tools/schemas.py`. Hash rule as in Phase 1. Tests: `NoiseModel()` hashes and runs identically to `quiet_noise_model()`; the summary lists heating when `S_E` is set and nothing when it is not; the device round trip is exact for both presets.

**2.6 `error_model()`.** New `qutip_trap/benchmarks/error_model.py`: `ErrorModel` (per native gate kind the infidelity from `gate_channel`, the SPAM errors from the table, the durations from the schedule, with the naming discipline of 0.6) and `to_ionq_noise()`, `to_quantinuum_error_params()`, `to_qdk_qubit_params()` with the conversions in their docstrings (IonQ: `F_avg = 1 - r/2` and `1 - 3r/4`; the QDK strings unit-suffixed). `Machine.error_model()` calls it. Tests: `to_ionq_noise()['r_1q']` recomputed from `gate_channel`'s infidelity by the stated formula; the RB budget's `predicted['r_channel']` and the error model's single-qubit number agree within the budget's stated tolerance; the QDK strings match the estimator's regex.

**2.7 The Qiskit adapter on a machine.** `qutip_trap/interop/qiskit.py`: `QutipTrapBackend(machine, **run_options)`; `get_backend` returns a backend on `presets.yb171_chain(n)`; options flow through `Physics`/`Numerics`/`Readout`; `DevicePreset` accepted and wrapped, warning. `tests/test_interop_qiskit.py` extended with a `readout="full"` run through the objects.

Exit criteria for 0.3.0: no `gate_drives=` outside the roles tests; `docs/examples.md` written around the machine throughout; the app's override code deleted; `docs/deprecations.md` lists every rewrite with its removal version; the suite passes with deprecation warnings as errors.

## 6. Phase 3: 0.4.0, jobs, the record, docs, policy

**3.1 `RunSpec` and `Job`.** New `qutip_trap/run/spec.py`: `RunSpec` (circuit, shots, seed, machine hash, the three option objects, level, label) with `to_dict()`/`from_dict()` and a schema; `Job` with `status()`, `result()`, `cancel()`, `progress`, `record()`; `Machine.submit(circuit, shots, seed=)` running in a worker process built on the existing `dynamics/parallel.py` map; `RunRecord` and `last_record` become `Job.record()` with the old names as aliases. The app's `JobSpec`, `execute` and `workers.py` move onto them. Tests: `submit().result()` equals `run()`; cancel stops within one pulse; the spec round trip; the app's `test_workers.py` on the core job.

**3.2 The traces and the GATE_LOCAL register.** `Traces.mode_marginal: dict[int, np.ndarray] | None` (opt-in through `Numerics.integration.store_marginals`) and `Traces.wall_time_s` per pulse in `dynamics/engine.py`; the register after every step in `GateLocalReport` (or the idle channels) in `run/gate_local.py`. The app's Level 3 heatmap and Level 1 GATE_LOCAL view read them and delete their re-simulation and composition code. Tests: the marginal's mean equals `mode_occupations` at every stored time; the per-step register composed from the channels equals the reported one.

**3.3 `qutip_trap.physics` closed forms and `qutip_trap.experimental`.** `physics.py` exports the closed forms and presets the app imports privately (Mathieu stability, the Lamb-Dicke and zero-point closed forms, the sideband transfer, Harty's and Kirchmair's models, the readout apparatus presets, the CODATA constants); `qutip_trap/experimental/__init__.py` gathers the M12 transport records and functions, the tomography internals (`choi_least_squares`, `project_cptp`), `filter_function` and `frozen_excitation_bounds`, with the versioning disclaimer in its docstring; `qutip_trap.api` keeps exporting them unchanged. The app's `core.py` imports only from `qutip_trap`'s documented modules and `CORE_GAPS` becomes empty; its provenance-coverage test asserts that.

**3.4 Docs and policy.** `docs/` reordered as the ladder: quickstart, then one page per rung (`machine.md`, `circuit.md`, `schedule.md`, `dynamics.md`, `physics.md`) and one for the laboratory, with `conventions.md` (its first section the units, bit order, tensor order, seed invariants and vocabulary), `limits.md` and `physics_notes.md` unchanged; `docs/deprecations.md` complete; the public-surface test requires every rung name on its page; the seed contract written down in `conventions.md` exactly as the code has it (same `(shots, samples, seed, machine hash)` reproduces every shot; a different `shots` does not, because of the contiguous sample blocks; integrator and cap-rule changes may move sampled outcomes between minor versions). `docs/README.md` updated. PLAN.md Section 14.6's "core contract" paragraph amended to name the machine and the job.

**3.5 First removals.** Remove what was deprecated in 0.2.0 and has had two minor releases: `DevicePreset.run_kwargs()`, the old exporter names, `quiet_noise_model()`. The `run` keyword arguments and `SolverOptions` (deprecated in 0.3.0) stay until 0.5.0. Each removal deletes its `deprecations.md` entry into a "removed" table with the version.

Exit criteria for 0.4.0: `CORE_GAPS` empty and the app's tests green on the public modules alone; every public name documented (the surface test); the import budget held; the check scripts green; the six-click path of the app's exit criterion still works.

## 9. Risks and how each is caught

- **A moved device hash** invalidates cached tables and silently changes calibration keys. Caught by the digest test of 1.1 against the captured 7a26a27 digests and by the rule that default-valued new fields do not enter the digest.
- **Import-time regression** from the lazy root pulling qutip early. Caught by the 0.5 test; the remedy is keeping the root's `__getattr__` free of any eager submodule import.
- **The freeze test and the plan render drifting.** Caught by landing the `p17_interfaces.md` amendment, the re-render and the code in one change; the freeze test fails otherwise.
- **A `Circuit` default changing existing calls.** The third positional argument stays accepted; `measure=None` is the only new meaning and it applies only when the argument is absent. Caught by `tests/test_compiler.py` and the executed docs examples.
- **Typed experiment results breaking `calibration/experiments.py`**, which reads `fitted` by key. The base class keeps `fitted` and `value()`; the subclasses add attributes. Caught by the parametrised equality test of 2.2.
- **The v2 IonQ character order** settled wrongly. Caught by 0.4's fixture being written from the primary source before the exporter changes, and by the vendor survey's note that a Bell state cannot detect the error.
- **Deprecation noise in the app** during Phases 1 and 2. The app moves to the new shape within the same release window; the suite runs with the warning as an error from 2.1 on.
- **CI time**: qiskit in the dev group adds about a minute of install; the app's view-model suite is already twelve minutes. Watch the core job's total; if it passes twenty minutes, move the adapter test behind the extra and a separate job.
- **The plan's own estimates.** They assume the tree's conventions are followed and no physics changes; a phase that starts to touch physics has left the plan and should stop.
